# Authentication Architecture & Google OAuth Design Note

## 1. Overview

This document specifies the authentication system for Kaaj.
Google OAuth 2.0 is the only authentication method.
The system does not support password authentication or custom registration forms.

The authentication system uses:
- The Authorization Code Flow with Proof Key for Code Exchange (PKCE).
- Cryptographically signed ID tokens verified against Google public keys (JWKS).
- Encrypted storage for refresh tokens using AES-256-GCM.
- Server-side sessions stored in PostgreSQL with HttpOnly cookies.
- Transparent tenant isolation via the scoped Prisma client.

## 2. Data Models (Prisma)

Update the `User` model and add the `Session` model in [schema.prisma](file:///E:/personal-projects/kaaj/apps/api/prisma/schema.prisma):

```prisma
model User {
  id                   String    @id @default(uuid())
  googleSub            String?   @unique
  email                String    @unique
  name                 String?
  picture              String?
  encryptedRefreshToken String?
  createdAt            DateTime  @default(now())
  updatedAt            DateTime  @updatedAt

  sessions             Session[]
  categories           Category[]
  entries              Entry[]
  manifests            EntryManifest[]
  chunks               Chunk[]
  assets               AssetMeta[]
  maintenanceState     MaintenanceState[]
  leases               JobLease[]
  revisions            EntryRevision[]
  tags                 Tag[]
  entryTags            EntryTag[]
  shareLinks           ShareLink[]
}

model Session {
  id        String   @id
  userId    String
  expiresAt DateTime
  createdAt DateTime @default(now())

  user      User     @relation(fields: [userId], references: [id], onDelete: Cascade)

  @@index([userId])
  @@index([expiresAt])
}
```

### Key Considerations:
1. `googleSub` is unique. Lookups by Google subject map to exactly one `User`.
2. `Session.id` contains at least 32 cryptographically random bytes (hex-encoded to 64 characters).
3. `Session` links to `User` with `onDelete: Cascade`.

## 3. Environment Configuration & Validation

Validate all environment variables with Zod at server startup:
- `GOOGLE_CLIENT_ID`: Google OAuth client ID (string, required).
- `GOOGLE_CLIENT_SECRET`: Google OAuth client secret (string, required).
- `GOOGLE_REDIRECT_URI`: OAuth callback redirect URI (valid URL, required).
- `TOKEN_ENC_KEY`: Symmetric encryption key (at least 16 characters; derives a 256-bit key).
- `SESSION_TTL_DAYS`: Session time-to-live in days (integer, default 30).
- `GOOGLE_TOKEN_URL`: Google token endpoint URL (optional, defaults to `https://oauth2.googleapis.com/token`).
- `GOOGLE_JWKS_URL`: Google JWKS URL (optional, defaults to `https://www.googleapis.com/oauth2/v3/certs`).
- `FRONTEND_URL`: Web application URL (defaults to `http://localhost:3000`).

## 4. Encryption Module (AES-256-GCM)

Create [crypto.ts](file:///E:/personal-projects/kaaj/apps/api/src/auth/crypto.ts) to encrypt and decrypt sensitive tokens:
1. **Algorithm**: `aes-256-gcm`.
2. **Key Derivation**: Derive a 32-byte key from `TOKEN_ENC_KEY` using SHA-256 (or parse 64 hex characters).
3. **Initialization Vector (IV)**: 12 random bytes generated per encryption call.
4. **Auth Tag**: 16-byte authentication tag generated by the cipher.
5. **Serialization Format**: `iv:authTag:ciphertext` in hexadecimal string representation.

## 5. Backend OAuth 2.0 Endpoints (Hono)

Implement the following endpoints in [index.ts](file:///E:/personal-projects/kaaj/apps/api/src/index.ts):

### 5.1 `GET /auth/google`
1. Read the existing session cookie.
2. Determine if the user has a stored refresh token.
3. Generate a cryptographic `state` (16 bytes random hex).
4. Generate a PKCE `code_verifier` (32 bytes random base64url).
5. Compute the `code_challenge` using SHA-256 on `code_verifier` (base64url).
6. Store `state` and `code_verifier` in short-lived HttpOnly cookies (`kaaj_oauth_state`, `kaaj_oauth_verifier`) with a 10-minute expiry.
7. Construct the Google authorization URL:
   - Base URL: `https://accounts.google.com/o/oauth2/v2/auth`
   - `client_id`: `GOOGLE_CLIENT_ID`
   - `redirect_uri`: `GOOGLE_REDIRECT_URI`
   - `response_type`: `code`
   - `scope`: `openid email profile https://www.googleapis.com/auth/drive.file`
   - `state`: generated state
   - `code_challenge`: computed challenge
   - `code_challenge_method`: `S256`
   - `access_type`: `offline`
   - `prompt`: `consent` only if the user has no stored refresh token.
8. Redirect the user agent to the authorization URL.

### 5.2 `GET /auth/google/callback`
1. Validate query parameters `code` and `state`.
2. Read `kaaj_oauth_state` and `kaaj_oauth_verifier` cookies.
3. Compare the received state with the cookie state. Reject on mismatch with HTTP 400.
4. Clear the temporary OAuth cookies.
5. Send a POST request to `GOOGLE_TOKEN_URL` with `code`, `code_verifier`, `client_id`, `client_secret`, `redirect_uri`, and `grant_type=authorization_code`.
6. Parse the JSON response containing `id_token`, `access_token`, and optional `refresh_token`.
7. Verify the `id_token`:
   - Fetch public JWKS keys from `GOOGLE_JWKS_URL`.
   - Match the JWT header key ID (`kid`).
   - Verify the RSA-SHA256 signature using the public key.
   - Assert `aud` matches `GOOGLE_CLIENT_ID`.
   - Assert `iss` is `https://accounts.google.com` or `accounts.google.com`.
   - Assert `exp` is in the future.
8. Extract user profile: `sub`, `email`, `name`, `picture`.
9. Upsert the `User` record in PostgreSQL by `googleSub`.
10. If `refresh_token` is present, encrypt it with AES-256-GCM and persist it in `encryptedRefreshToken`.
11. Remove expired sessions from PostgreSQL.
12. Create a new `Session` record with a random 32-byte ID and `expiresAt` calculated from `SESSION_TTL_DAYS`.
13. Set the session cookie `kaaj_session`:
    - `httpOnly: true`
    - `sameSite: 'Lax'`
    - `secure: process.env.NODE_ENV === 'production'`
    - `path: '/'`
    - `expires`: session expiration date
14. Redirect to `FRONTEND_URL`.

### 5.3 `POST /auth/logout`
1. Read the `kaaj_session` cookie.
2. If present, delete the matching `Session` record from PostgreSQL.
3. Clear the `kaaj_session` cookie (`maxAge: 0`, `path: '/'`).
4. Return HTTP 204 No Content.

### 5.4 `GET /auth/me`
1. Read the `kaaj_session` cookie.
2. If no valid session exists, return HTTP 401 Unauthorized.
3. Fetch the user details.
4. Return `{ id, email, name, picture }` with HTTP 200.

## 6. Auth Guard Seam & Scoped Prisma Client

Update [guard.ts](file:///E:/personal-projects/kaaj/apps/api/src/auth/guard.ts):
1. Skip authentication on public routes (`/health`, `/shared/*`, `/auth/google`, `/auth/google/callback`, `/sync/ws`).
2. Read the `kaaj_session` cookie.
3. If the cookie exists, query PostgreSQL for an active session (`expiresAt > now()`).
4. In test mode (`APP_MODE === 'test'`), allow fallback to the `Authorization` header when provided.
5. If the session is invalid or missing:
   - If the request contains `Accept: text/html`, return HTTP 302 redirect to `${FRONTEND_URL}/login`.
   - For all other requests, return HTTP 401 JSON (`{ error: 'Unauthorized' }`).
6. Set `c.set('userId', session.userId)` and `c.set('auth', { userId, subject })`.
7. Route handlers invoke `forUser(c.get('userId'))` from [client.ts](file:///E:/personal-projects/kaaj/apps/api/src/db/client.ts) to execute scoped database queries.

## 8. E2E Testing Strategy

Create [auth.spec.ts](file:///E:/personal-projects/kaaj/e2e/auth.spec.ts):
1. **Mock Endpoints**:
   - Provide a local stub server for Google Token and JWKS endpoints.
   - Point `GOOGLE_TOKEN_URL` and `GOOGLE_JWKS_URL` to the stub server.
2. **Test Cases**:
   - Google callback with valid code creates user and session records.
   - Google callback with invalid state returns HTTP 400.
   - `GET /auth/me` returns user profile when called with a valid session cookie.
   - Protected route returns HTTP 401 when requested without a session cookie.
   - `POST /auth/logout` deletes the session from the database and subsequent `GET /auth/me` returns HTTP 401.
   - Second login with identical `googleSub` reuses the user and does not duplicate records.

## 9. Google Cloud Console Configuration

Follow these steps in Google Cloud Console:
1. **Create/Select Project**: Open the Google Cloud Console and select or create your Kaaj project.
2. **Configure OAuth Consent Screen**:
   - Select **APIs & Services** > **OAuth consent screen**.
   - Choose User Type: **External**.
   - Fill in App Information: App name (`Kaaj`), User support email, Developer contact email.
   - Add Scopes: `openid`, `.../auth/userinfo.email`, `.../auth/userinfo.profile`, and `https://www.googleapis.com/auth/drive.file`.
   - Set Publishing Status to **In production** to prevent 7-day refresh token expiration.
3. **Create OAuth 2.0 Client Credentials**:
   - Navigate to **APIs & Services** > **Credentials**.
   - Click **Create Credentials** > **OAuth client ID**.
   - Select Application type: **Web application**.
   - Add Authorized JavaScript Origins:
     - Development: `http://localhost:3000` and `http://localhost:3001`
     - Production: `https://your-domain.com`
   - Add Authorized Redirect URIs:
     - Development: `http://localhost:3001/auth/google/callback` and `http://localhost:3000/auth/google/callback`
     - Production: `https://your-domain.com/auth/google/callback`
4. **Copy Secrets to Environment**:
   - Set `GOOGLE_CLIENT_ID` in `.env`.
   - Set `GOOGLE_CLIENT_SECRET` in `.env`.
   - Set `GOOGLE_REDIRECT_URI` in `.env`.
